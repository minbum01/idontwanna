## 1. 어떻게 확인했나 (검증 방법)

- 실제로 현재 소스(`포켓북_전체.html`, 6/22 기준 **128쪽**)를 **헤드리스 Chrome `--print-to-pdf`** 로 PDF 재생성(`_검증_전체_new.pdf`).
- 생성된 PDF를 **PyMuPDF(fitz)** 로 직접 열어:
  - 페이지 크기(pt→mm), 폰트 임베딩 목록, 이미지 색공간·픽셀 수를 추출
  - 표지·간지·막대차트·초조밀 색인 등 대표 페이지를 이미지로 렌더해 **배경·그라데이션·괘선이 실제로 찍히는지 눈으로 확인**

> ⚠️ 참고: 기존에 폴더에 있던 `포켓북_전체_A5.pdf` 는 **6/18에 만든 34쪽짜리 구버전**입니다(현재 소스는 128쪽). 그 파일에서는 일부 막대그래프가 비어 보였는데, 이는 출력 결함이 아니라 **옛 버전이라서** 입니다. 최신 소스로 다시 뽑으면 정상 출력됩니다.

## 2. 항목별 점검 결과

### 2-1. 페이지 크기 · 도련(Bleed) 🟢
- PDF 실측 **154.2 × 215.9 mm** = 의도한 `A5(148×210) + 사방 3mm 도련`과 일치.
- `pocketbook.css`에 `@page{size:154mm 216mm;margin:0}` 로 정확히 지정되어 있고, 안쪽(제본)/바깥 여백(gutter)도 verso/recto별로 자동 적용됨.
- **누락:** 재단선(crop mark)·맞춰찍기(registration) 마크는 없음. → 풀블리드 정사이즈 PDF이므로 인쇄소가 148×210으로 재단 가능. **입고 시 "사방 3mm 도련 포함, 148×210 재단" 이라고 명시**하면 됩니다.

### 2-2. 해상도 🟢 (표지만 예외 → 2-6 참고)
- 128쪽 전체에서 **래스터(픽셀) 이미지는 표지 1장뿐**. 본문의 모든 표·막대·로그스케일 차트·매트릭스는 **CSS/SVG 벡터** → 확대해도 깨지지 않고 인쇄 해상도 제한이 없음.
- "해상도 부족"으로 문제 될 곳은 표지 외엔 없음.

### 2-3. 폰트 임베딩 🟢
- 본문 폰트 **Pretendard**(Regular/Medium/SemiBold/Bold/ExtraBold)가 전부 **서브셋 임베딩**(Type0/TrueType)됨 → 인쇄소 PC에 폰트가 없어도 글자 깨짐·치환 없음.
- CSS는 제목/본문/숫자를 모두 Pretendard로 통일하므로, 함께 `@import` 된 Google Fonts(나눔명조·IBM Plex)는 실제로는 미사용 → PDF에도 안 들어가 있어 문제 없음.
- **유의 1 — 생성 시 인터넷 필요:** 폰트가 jsDelivr/Google CDN에서 `@import` 로 로드됩니다. **PDF를 뽑는 그 순간 인터넷이 끊겨 있으면** 폰트가 시스템 기본글꼴로 대체될 수 있음. → 항상 온라인 상태에서 생성하고, 생성 후 위 임베딩 점검을 1회 권장.
- **유의 2 — Type3 글리프:** PDF에 이름 없는 Type3 폰트가 일부 보이는데, 이는 Chrome이 특수기호(▸ ↳ 〔〕 등)를 PDF 안에 자체 포함시킨 것으로 **PDF에 내장되어 출력에 문제 없음**(외부 폰트 의존 아님).

### 2-4. 배경색 · 그라데이션 인쇄 🟢
- 막대그래프의 파란 그라데이션, 간지의 페이지 전체 그라데이션, 표 헤더(네이비)·연파랑 틴트·교차행 음영이 **모두 정상 출력**됨을 렌더 이미지로 확인.
- 단, 이는 **헤드리스 Chrome `--print-to-pdf`(배경 기본 인쇄)** 기준입니다. 사람이 브라우저에서 `Ctrl+P` 로 뽑을 때는 **"배경 그래픽" 옵션을 반드시 켜야** 합니다(꺼져 있으면 헤더밴드·차트·틴트가 전부 흰색으로 사라짐). → 5장 참고.
  - (참고: CSS에 `print-color-adjust:exact` 선언이 없어서, 브라우저 수동 인쇄 시 배경 누락 위험이 있습니다. 안전하게 하려면 추가 권장 — 4장.)

### 2-5. 색공간 — CMYK 🟡 **(가장 중요한 주의점)**
- 생성된 PDF의 색공간은 **RGB(sRGB / ICCBased RGB)** 입니다. 브라우저·Chrome 계열의 "PDF로 인쇄"는 **CMYK를 만들 수 없습니다**(항상 RGB).
- **무엇이 문제인가:**
  - **오프셋 인쇄소**는 RGB를 받아 CMYK로 변환해 찍습니다. 이 과정에서 **채도 높은 파랑이 가장 잘 틀어집니다.** 이 책은 핵심색이 진한 청색(`#2f55a4`, `#33529e`, 그라데이션 끝 `#1f3a6e`)이라 **CMYK 변환 시 보라끼로 칙칙해질 수 있음.**
  - 아주 옅은 틴트(`#eef3fb`, `#f6f8fc` 등 2~4% 수준)는 오프셋에서 **아예 안 찍히거나 얼룩질** 수 있음.
  - 본문 글자색이 순검정(#000)이 아니라 **네이비(`#1f2b45`)** 라, CMYK에서 4색 혼합이 되어 **작은 글씨가 인쇄 핀이 안 맞으면 흐릿**해질 수 있음. (디자인 의도는 "2도"지만 데이터상은 풀컬러 RGB)
- **판단 기준:**
  - **디지털 인쇄/POD(소량)** → 대부분 RGB 입고를 받아 자체 프로파일로 출력. **지금 PDF로 진행 가능.**
  - **오프셋(대량·고급)** → 입고 전 **CMYK 변환**을 권장(4장 참고). 특히 청색 계열은 변환 후 교정쇄(샘플) 확인 필수.

### 2-6. 표지 이미지 🔴 **(수정 필요)**
- 표지는 본문과 달리 **래스터 PNG**(`표지_앞.png`, 원본 1788×2450)인데, `object-fit:cover` 로 154×216 틀에 맞추면서 **좌우가 잘려** PDF에는 1434×2450로 들어감.
  - 결과: 좌측 "해커스공무원" 글자 왼쪽 끝과 "필기/배치표" 좌측이 살짝 잘림.
  - 유효 해상도 **가로 약 237 DPI** (인쇄 표준 300 DPI 미만 — 디지털 인쇄는 무난, 고급 오프셋엔 부족).
- HTML 주석에도 *"최종 출력은 원본 디자인 파일로"* 라고 적혀 있음 → **예정대로 인쇄용 표지 원본(가급적 벡터 또는 300DPI+·도련 포함 CMYK)으로 교체**하면 해결.

### 2-7. 미세 요소 — 얇은 선·초소형 글씨 🟡
- 시·군 색인 표가 매우 조밀: 글자 **5.4~6.6pt**, 괘선 **0.2~0.42mm(≈0.57~1.2pt)**, 연회색선(`#f2f4f7`).
- 화면/디지털 인쇄에선 읽히지만, **오프셋에서는 0.2mm 헤어라인·초연회색 선이 끊기거나 사라질** 수 있고 5.4pt는 가독 한계선.
- 권장: 색인 최소 글자 **6pt 이상**, 괘선 **0.25mm 이상·색을 조금 더 진하게**(예: `#e3e9f2`) — 여유 있을 때 조정.

| 5 ⚪ | 재단선(crop mark) 없음 | — | 정사이즈 풀블리드라 불필요. 입고 시 도련 명시 |
| 6 ⚪ | 구버전 `포켓북_전체_A5.pdf`(34쪽) 잔존 | 혼동 | 삭제 또는 최신본으로 교체 |

### 권장 CSS 추가 (3번 안전장치)
`pocketbook.css` 의 `@media print{ ... }` 안에 한 줄:
```css
*{ -webkit-print-color-adjust:exact; print-color-adjust:exact; }
```
→ 누가 어떤 브라우저로 인쇄해도 헤더밴드·차트·틴트 배경이 빠지지 않게 보장.

## 4. CMYK가 필요할 때 — 변환 방법 (오프셋용)

브라우저로는 CMYK PDF를 못 만들므로, RGB PDF를 받은 뒤 변환:
1. **인쇄소에 맡기기(가장 안전):** "RGB로 제작했으니 귀사 프로파일로 CMYK 변환해 달라" + **청색 계열 교정쇄 확인**. 대부분 표준 워크플로.
2. **직접 변환:** Acrobat Pro(인쇄물 제작 → 색 변환, 프로파일 예: `KSCMYK` 또는 인쇄소 지정)나 Ghostscript로 변환 후, 청색·옅은 틴트가 의도대로 나오는지 확인.
3. 변환 후엔 **반드시 실물 교정쇄(샘플 1부)** 로 색을 눈으로 확인하고 양산.

## 5. PDF를 "제대로" 뽑는 방법

### A. 인쇄소 입고용 (권장) — 헤드리스 Chrome
페이지 크기·여백·배경이 자동으로 정확히 잡힙니다. (이 보고서 검증에 쓴 방식)
```
chrome --headless=new --disable-gpu --no-pdf-header-footer ^
  --virtual-time-budget=40000 --run-all-compositor-stages-before-draw ^
  --print-to-pdf="포켓북_전체.pdf" "file:///.../포켓북_전체.html"
```
- 생성 후 PyMuPDF 등으로 **페이지 크기(154×216)·폰트 임베딩**을 1회 확인.
- 인터넷 연결 상태에서 실행(폰트 CDN 로드).

### B. 사람이 브라우저에서 직접 인쇄할 때 (`Ctrl+P`)
다음을 **모두** 설정하지 않으면 크기·색이 틀어집니다:
- 용지 크기: **사용자 지정 154 × 216 mm** (기본 A4로 두면 축소·여백 발생)
- 여백: **없음(None)**
- 배율: **100% (맞춤 끄기)**
- **배경 그래픽: 켜기** ← 안 켜면 헤더·차트·틴트가 흰색으로 사라짐
- 머리글/바닥글: 끄기

## 6. 종합 의견

- **디지털 인쇄(소량/POD):** 표지 원본만 교체하면 **지금 상태로 입고 가능.** 본문 품질(벡터·폰트·도련) 문제 없음.
- **오프셋(대량):** ① 표지 원본 교체 → ② CMYK 변환(청색 교정 확인) → ③ (선택)색인 미세 요소 보강 → 진행.
- 가장 먼저 처리할 것은 **표지 원본 교체**와 **오프셋이면 CMYK 변환** 두 가지입니다. 나머지는 안전장치·다듬기 수준입니다.

*(검증용으로 생성한 최신 PDF: `_검증_전체_new.pdf` — 128쪽. 구버전 `포켓북_전체_A5.pdf`(34쪽)와 혼동 주의.)*
